# BuffettChart

当前已扩展为“长期指标页”：巴菲特、标普500与日经225均提供长期价格和去趋势图。标普与日经独立使用月度数据及模型；配置、来源、更新周期和展示规则见 [长期指标说明](docs/long-term-indicators.md)。下文原巴菲特分区说明继续有效，但“正文两图”仅指巴菲特区块。

巴菲特指数半静态展示页，挂载 `/buffett/`。顶部展示标准指数、去趋势偏离、趋势参考和 Z-score；正文保留标准与去趋势两张全历史图。页面支持手机横向查看完整图表，SVG 和合并后的完整计算快照可在浏览器下载。

当前真实快照仍为 1952Q1—2026Q2，共 298 季，数据核验日为 2026-10-07。末值：238.43%、+65.93%、143.69%、+1.50σ。本次架构优化没有刷新或修订任何实际数据。

## 固定区与更新区

最近 **8 个季度**保留在更新区；更早数据锁定。新增季度时，将移出窗口的最早季度保存为一个新的固定片段，不重写原历史文件。

| 层次 | 固定区 | 更新区 |
| --- | --- | --- |
| 源数据 | `data/fixed/baseline-v1.json` 原始完整基线；构建使用截至 2024Q2 的 290 季作为固定前缀 | `data/updates/snapshots/<版本>.json`，每版只包含最近 8 季，当前为 2024Q3—2026Q2 |
| 后续归档 | `data/fixed/extensions/<季度>.<哈希>.json`，每新增季度最多追加一个固定片段 | `data/updates/current.json` 小型版本入口；`audit/` 记录追加、修订前后值及采纳原因 |
| 网站发布 | `dist/fixed/`：压缩历史序列、绘图脚本、样式，均带内容哈希 | `dist/updates/recent.json`：8 季数字；`current.json`：模型、末值、日期和各分区哈希 |

`dist/index.html` 是稳定的页面框架，仅界面代码或样式版本改变时才改变。数据更新不会再重写网页、整张 SVG 或整份历史计算表；浏览器读取两区数据后使用统一模型生成图表和下载文件。新季度会改变全历史趋势及去趋势派生值，但不会改变固定原始 BI。

完整原始 298 季仍作为不可变基线保存，其中末 8 季仅是原始版本参照；当前有效的末 8 季来自更新区，避免将“保留旧基线”与“禁止近期修订”混为一谈。原始迁移 ZIP 和说明继续保存在 `archive/`。

## 构建与查看

Node.js 22+，无第三方依赖。

```sh
npm run build
npm test
npm run preview
```

打开 `http://127.0.0.1:4173/buffett/`。相同输入重复构建：文件内容和修改时间均保持不变。网页依赖 JavaScript 合并数据并绘图；禁用脚本时显示明确提示及当前模型数据链接，不显示未经检查的数值。

## 后续更新流程

准备一个候选 JSON，只放新增或待修订季度，`rows` 保持基线中每行的字段、单位、来源原值和质量标记。

```json
{
  "snapshot_id": "新的唯一版本标识，只使用字母数字下划线连字符",
  "updated_on": "实际核验日期 YYYY-MM-DD",
  "source_note": "官方发布、抓取来源与版本说明",
  "revision_reason": "仅修订时填写采纳原因",
  "rows": []
}
```

以上为字段示意，空 rows 不可应用。完整行格式可参考 `data/updates/snapshots/` 中的当前版本。候选可以是单季或多季，不需要复制整段老历史。

```sh
# 只校验、预览差异，不修改文件
npm run data:update -- candidate.json

# 仅新增季度，验证后保存新快照
npm run data:update -- candidate.json --apply

# 包含近期修订：用户决定采纳后，显式登记采纳
npm run data:update -- candidate.json --accept-revisions --apply

npm run build
npm test
```

工具会拒绝固定区改动、季度缺口、重复季度、非法日期、来源/单位不匹配、旧版本文件覆盖，以及基于过期入口生成的更新计划。近期修订必须带采纳原因并显式接受；审计记录保留前后完整行。新版本和固定片段先写好，最后切换入口文件。原版本不删除，回滚可在 Git 中恢复入口引用；不会直接覆盖旧快照。

数据没有变化时不新增版本、不刷新更新时间。仅重画、改样式、重新构建和部署也不会重置更新时间。未实现自动联网抓取。

## 增量包与 Cloudflare

构建前先另存旧的 `publication.json`，构建新版本后可只打包变化资源：

```sh
npm run package:update -- previous-publication.json work/update-package
```

输出必须为不存在的新目录。包内 `assets/` 仅有变化文件，另附版本清单与增量说明；它需要覆盖到**匹配的旧版本**上，不是可单独部署的完整网站。跨版本首次迁移应使用完整 `dist/`。增量包包含原清单和目标清单的哈希，便于核验基版。

正常接入现有 Cloudflare 项目：

```sh
npm run integrate -- G:/cloudflare/myapp
```

仅改写字节实际变化的资产；固定资源同名但字节不同会停止。现有旧版固定资产保留，便于已打开页面继续请求。首次迁移会核验并移除旧版重复生成的 SVG、完整 snapshot 和根目录脚本。目录与权限白名单、缓存规则、验证方法见 [Cloudflare 接入说明](docs/cloudflare.md)。

在 myapp 中执行 `npm test` 和 `npm run check`。不会自动推送 Cloudflare 仓库、修改 Access/D1/KV 或部署生产。

## 模型和新鲜度

标准指数 = 市值（百万美元）/1000/GDP（十亿美元 SAAR）×100；GDP 不再乘 4。全历史拟合 `ln(BI)=a+b*t`，每季 0.25 年；σ 分母为 n−2。去趋势 = `(BI/Trend−1)×100`，Z = `ln(BI/Trend)/sigma_log`；百分比与 Z 分开。历史估计段 1952Q1—1996Q3 共 179 季及固定比例永久不变。

以当前更新区快照的 `updated_on` 加 **5 个日历月**，按 Asia/Shanghai 日期严格判断“超过”。当前快照从 2027-03-08 00:00 起提示更新。浏览器首次加载、切回及每分钟检查；日期判断不使用网页构建日期。固定资源可长缓存，更新区每次重新验证。所有分区先校验哈希与期数，跨发布产生版本不一致时重读一次；仍失败则提示重试，不拼接错误版本。
